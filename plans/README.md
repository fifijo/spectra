## Findings considered and rejected

- **The Healer re-running the whole Playwright suite instead of reading the
  results file** — the catalogue already declares `reports/results.json` as
  the Healer's input and the config already writes it there. Re-running is
  the Healer's documented process, and changing it is a product decision, not
  a defect. Tracked as a direction note, not a plan.
- **The per-Scope folders being copies rather than the originals** — decided
  in `docs/adr/0002-scope-results-are-copies.md`. The ADR names the cost
  (`reports/results.json` is not copied) and the reason. Not a finding.
- **The catalogue and the agent templates naming the same paths twice** —
  decided in `docs/adr/0001-agent-catalogue.md`. A test that fails is
  preferred to a generator that loses the user's edit.
- **19 unused Page Object members** — dead API surface, but no behaviour is
  wrong and nothing regresses. Worth a cleanup pass, not a plan.
- **An unknown CLI flag printing a raw Node stack trace** — `parseArgs`
  throws in strict mode on purpose and a test asserts it
  (`src/__tests__/args.test.ts:133`). The exit code is right (1); only the
  message is ugly. Cosmetic.
- **`/* eslint-disable no-console */` in `src/utils/logger.ts`** — the repo
  uses Biome, not ESLint, so the comment is dead. One line, no plan.
- **The `spectra` npm script duplicating the `bin` entry; `.gitignore`
  missing `*.tgz`; `specs/` shipped in the tarball but never installed** —
  all small package hygiene. Fold them into whichever plan next touches
  `package.json` rather than giving them a plan of their own.

- **The Playwright MCP config is Cursor-only, while `claude-code` mode reads

  not a documentation fix; recorded as a direction note below.
- **`SPECTRA_SKIP_WEBSERVER` is not documented** — it is a repository-only
  switch for this repo's own config, and consumers have no equivalent. Not a
  finding.

## Direction notes (not plans)

Offered to the maintainer during the audit; none of them is a defect, and
none is scheduled here.

1. **A `--dry-run` that prints the three Agent prompts and exits.**
   `buildPrompt` (`src/agents/runner.ts:110-128`) is already a pure, tested
   function. The pipeline costs minutes and money per run and there is no way
   to see what it will do before it does it.
2. **Let the Healer consume CI results instead of re-running the suite.**
   The catalogue already declares `reports/results.json` as its input and
   the JSON reporter already writes it. The Healer's own instructions make
   it re-run Playwright locally, which cannot work in CI where the app is
   not running. This is what turns Spectra from a local tool into a CI tool.
3. **Let Spectra own the files it generates.** A manifest of generated
   `pages/` and `tests/` would let a re-run replace its own output instead
   of accumulating, and would let a batch attribute a file to a Scope. Fixes
   the "old tests keep running" problem at the root.
4. **Fail fast before spending an Agent.** Nothing checks that the URL
   answers, that `@playwright/test` is installed, that a Playwright config
   exists, or that MCP is available — so a misconfigured target surfaces
   minutes later, inside an agent, as a "healed" test file.
5. **Make the gate executable.** The Generator Gate is three files of prose
   that a human applies by hand, and the audit found the template violating
   it (plans 017 and 026). A `spectra gate` command — or a CI script that
   checks the rules: one tag per test, no hard-coded waits, semantic
   locators, one business-visible assertion per test — would turn the review
   loop into a build step. The rules already exist; only the checker is
   missing.
6. **A docs-drift check in CI.** The shipped documents name paths, flags
   and scripts; nothing verifies they exist. This repository has now had
   three rounds of documentation drift (plans 007 and 013, then this audit),
   and every round found the same class of problem. A small script that
   extracts the paths and commands from the shipped docs and checks them
   against the tree would stop it recurring.
7. **Let the Healer file an issue instead of quietly giving up.** The
   CI/Healer policy already classifies failures as `bug`, `locator`, `flake`
   or `env`; a `bug` currently ends as a failing test with a `@blocked` tag.
   Turning that into a filed issue — with the evidence the Healer already
   collects — is what makes the pipeline useful in a team.
